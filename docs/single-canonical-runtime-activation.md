# Candidate activation plan — NOT AUTHORIZED / NOT EXECUTED

This is an offline decision package. The candidate intentionally has no real
activation writer: `activate_installed` always denies. The existing installation,
main, old source and launchers remain unchanged. Candidate test fixtures and
passing offline tests do not establish host fencing or native readiness.

## Supported surface inventory and closure

The future owner-approved stopped operation must supply a complete finite list
of every supported package root and its launch surfaces: console scripts, `-m`
modules, editable/source/worktree copies, installed wheel/site-packages copies,
old CLI/inert/Home/v1/v2/supervised paths, and associated helpers. Resolve each
launcher to the implementation, not just its alias. Record exact absolute path,
filesystem identity, version, source tree, executable/entry point and bounded byte
inventory, including cached bytecode and native extensions. A missing, ambiguous,
reparse/aliased, hard-linked or unknown supported root stops activation. Backups
are inert archives outside import/search paths, not runnable retained packages.

The admission universe is explicitly operator-enrolled and reviewed. It is not a
filesystem search, arbitrary-host attestation or permission to infer that unknown
Python processes are runner actors. No generic process-name allowlist is used to
admit a worker. An unsupported/unfenceable supported surface is an architecture
blocker, never a waived row or self-declared `legacy_fenced` boolean.

Candidate surface matrix:

| Surface | Enforcement |
| --- | --- |
| New wheel console/module policy command | fixed ProgramData locator, exact wheel/venv package+executable+project, manifest, coverage and durable anchor |
| New source/worktree/editable copy | rejected by installed-layout gate before locator/native creation |
| New old-style CLI, host/runtime or concrete CreateProcessW wrapper | concrete one-use creation scope absent: deny |
| Hidden worker | authenticated offer/parent channel; no parent creation scope |
| Existing independent old implementation | NOT currently fenced: separately gated whole-package decommission |
| Old module/source/native-extension/bytecode launch | entire enumerated implementation becomes inert; post-transform exact inventory required |
| Generic diagnostic subprocess utility | exact current/base interpreter or already fixed package-observation executable only; direct player/arbitrary helper rejected; existing package/command gates unchanged |
| Read-only Status / help | no actor creation, no migration, no stop authority |

## Stopped activation transaction (future separately approved operation)

1. Obtain explicit owner approval for the exact reviewed candidate and enumerated
   legacy targets. Preserve prior source, index, reports and private state. The
   offline fixture capability is not an installation capability.
2. Hold the existing protected global lifecycle mutex; reject abandonment. Prove
   complete player absence and no legacy runner using exact retained identities,
   all enumerated local stores closed/READY, no transition guard, no unresolved
   generation, no uncertain worker/helper. Process absence alone is insufficient.
3. Pin path identities and exact source bytes; freeze the inventory and launch
   mapping. Write/read back protected pending migration intent with immutable
   backup seal before any transformation. Deny concurrent supported writers.
4. Use protected no-reparse write-through replacement/readback to decommission
   every enumerated executable package form, including caches, extensions and
   source files. The offline executor exercises the exact transformation on
   copied fixtures only; its ordinary file writes do NOT certify this future
   Win32 installation durability. Interruptions retain pending state; resume only
   byte-identical before/after entries with independently verified backups and
   renewed stopped authority. Partial or foreign bytes require review; never
   automatically restore runnable old code.
5. Re-exercise each old entry/leaf with intercepted process creation and verify
   complete post-inventory and directory identity. Reintroduced files, moved
   roots, changed version/bytes or unproved target coverage invalidate activation.
6. Install the reviewed wheel into one dedicated Windows venv (Lib/site-packages
   and its exact Scripts/python.exe), not editable/source mode. Pin its manifest,
   candidate tree and project root. Provision the fixed KnownFolder ProgramData
   `ClashRush-native/var` using operator+SYSTEM-only protected DACLs and existing
   durable/no-reparse primitives. No environment-selected alternative root exists.
7. Only after every join succeeds may a separately reviewed activation writer
   create the schema-1 installation descriptor (`ACTIVATED`, exact project,
   package, executable, source_tree, manifest, coverage receipts, decision
   provenance) and initial matching STOPPED anchor. Descriptor/receipt digests
   are derived from bytes, not a trusted boolean. Missing activation, coverage,
   manifest, store or identity denies all candidate native creation.
8. Read back every target, DACL, path identity, receipt and store. Rerun installed
   non-live rejection/preflight from outside source. Do not launch BlueStacks.
   Native A2/A3 still needs a separate exact owner gate after offline review.

## Failure and restart policy

No TTL expiry, stale deletion, numeric-PID stop, close-as-kill, activation on read,
force-READY or automatic rollback. PREPARING/creation-pending/STOP_INTENT and every
surviving local/host transition guard remain blocking across process death.
SQLite closure, READY and host CLOSED must agree; response loss after matching
closure permits only read-only status/duplicate classification, never a recovered
frozen stop grant. Reconciliation of ambiguous activation or runtime state needs
separate explicit authority. This plan creates no privileged service or scheduler.
