## Closed supported launch universe

locator and durable occupancy anchor. Source/worktree/copied/legacy compositions
have no native grant. All candidate native process creation leaves must require a
same-parent/thread one-use create scope issued by common policy bootstrap after
host PREPARING/local ACTIVE/readback. The worker never receives this scope.
Read-only metadata and help are not native admission.

Legacy activation uses an explicit finite inventory of supported source trees,
editable installations, wheels/site-packages, module and console launchers and
helper executables. Exact path, filesystem identity, version and byte manifest
are frozen; unknown or incomplete coverage denies activation. Inventory is not
arbitrary-host attestation. Unsupported unknown code cannot be asserted safe.
An old launcher alias is not the implementation: decommission the actual package
and concrete native leaves, including cached bytecode. Preserve backups as inert
archives. Independently execute the old code with intercepted OS leaves before
and the transformed disposable installation after decommission. Keep the original
RED probe/result verbatim. Actual host transformation is a separate owner gate.

Transformation is stopped-only: protected mutex, complete player absence, every
legacy store closed/READY with no guard/uncertainty, no live old runner, exact
source/identity readback, durable pending journal, byte-verified backup, bounded
idempotent replacement, post-verification, then activation receipt. Crash or
uncertain identity leaves pending and denies admission; never roll back to runnable
old code automatically. The offline tool may operate only disposable fixtures;
no actual activation capability is issued in this candidate. Reintroduction or
changed inventory/paths/version invalidates the activation proof.
