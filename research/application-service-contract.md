# Application-service contract and donor-reuse inventory

## Scope and safety decision

This slice defines a static, local application-service contract only. It does not activate or reconcile lifecycle state, select scheduler work, create processes, import Win32/device code, perform input, authorize a transaction, spend resources, call a network or Discord API, or read runtime/private data. `LifecycleSupervisor.start` remains sealed and unchanged.

The application service is the sole adapter-facing boundary. Local controls and a future Discord adapter may construct an `Actor` and closed `Command`, then call `LocalControlAdapter.submit` (or an equivalent future adapter over `ApplicationService.execute`). The supported `LocalControlAdapter` API contains only `submit`, and neither that API nor any submitted result returns the service or an injected scheduler, lifecycle, setup, diagnostic, transaction, resource-gate, or executor capability. Discord remains a transport/authorization adapter only: it owns no gameplay, spending, scheduling, lifecycle, or diagnostic implementation.

This is an honest trusted-process contract, not a Python security sandbox. Ordinary supported adapter use must traverse exact service-owned validation and authorization, and malformed or absent private adapter state fails closed. In-process code able to inspect `__globals__` or `__closure__`, walk `gc` or frames, invoke `object.__getattribute__` or `object.__setattr__`, monkeypatch module/class/function objects, mutate underscored internals, attach a debugger, or inspect native memory is trusted code and can corrupt the process. Recovering or replacing private authority by those techniques is explicitly outside the contract. No reflection-proof, capability-unrecoverability, or hostile-code-isolation claim is made.

The largest relevant licensed seam is BasePilot's 63-line `BotController` class. Its single-façade shape is adapted cleanly, but its implementation is not reusable because it hands the UI a path to a directly owned gameplay `Bot`, creates execution threads, reads profile settings, and lacks every required durable safety gate. This repository's `LocalControlAdapter` therefore accepts only an exact `ApplicationService`, rejecting subclasses and attribute-compatible fakes that could replace authorization. It keeps one private trusted-process dispatch binding and no module-global registry of live services; all orchestration authority stays behind the service's injected `Protocol` ports.

## Closed contract

`CommandKind` is the complete application command vocabulary:

- `SETUP`
- `RUN`, `PAUSE`, `RESUME`, `STOP`
- `STATUS`
- `QUARANTINE`, `UNQUARANTINE`
- `DEBUG_START`, `DEBUG_STATUS`, `DEBUG_STOP`

The vocabulary uses **Team** for an account group. `account_ref` identifies one account within a Team. The word **troop** is reserved for in-game units and does not appear in this control model.

The command field matrix is closed. `SETUP` alone permits `resources`; `QUARANTINE` and `UNQUARANTINE` alone require and permit `account_ref`; `DEBUG_START` alone requires and permits `debug_minutes`; and `RUN`, `PAUSE`, `RESUME`, `STOP`, `STATUS`, `DEBUG_STATUS`, and `DEBUG_STOP` permit none of those optional fields. Every non-Setup resources value must be the empty exact `frozenset`. Irrelevant fields, non-exact resource collections, and non-`Resource` members reject before authorization or any other callback.

The adapter accepts only an exact `ApplicationService` and keeps one private dispatch binding. Missing or malformed dispatch state becomes a sanitized `ControlRejected`, not a raw attribute/type error. Dispatch uses the class implementation of `ApplicationService.execute`, never a mutable instance attribute. Every adapter-reachable service helper is likewise dispatched through the exact `ApplicationService` class implementation; instance attributes shadowing request validation, authorization, state/status loading, online checks, persistence, setup, admission, or intent copying cannot alter any command path. Mutation of the private binding or of module/class/function definitions is trusted-code corruption outside the supported API, not an attacker model this design claims to resist. The service accepts exact `Actor` and `Command` types. Actor, command, Team, account, and returned setup-generation references are exact strings matching `[A-Za-z0-9][A-Za-z0-9._:-]{0,127}`; booleans, subclasses, empty/whitespace values, path-like values, and longer references are rejected. All exact actor and command fields are read, validated, and copied within a sanitized ingress boundary before authorization. An exact frozen/slots request structurally corrupted by a missing field rejects as `ControlRejected` with no retained cause or context. Every later decision uses only the private snapshot. Authorization receives a fresh exact `Actor`, so callback mutation cannot change the already-snapshotted Team, kind, references, debug duration, or resources used by the service. Every command is authorized against its snapshotted exact Team and action, and authorization exceptions fail closed without exposing the exception text.

Every value crossing an injected port is treated as untrusted ingress. `DesiredStatePort.load` must return an exact `DesiredState` for the requested Team, an exact `ControlMode`, and an exact integer epoch in `0..2^63-1`. Mutating control/account/debug requests pass a fresh `Command` copy to `DesiredStatePort.persist`; returned intent validation remains bound to both the private pre-callback command snapshot and the loaded pre-callback desired epoch, so mutation of callback-owned values cannot forge a matching result. Only a service-owned scalar copy of an exact returned `DurableIntent` may be handed to the responsible port. It must match the snapshotted command reference, Team, kind, account reference, and debug duration, carry the transition's required exact mode, and carry exactly `loaded_epoch + 1`. Stale, repeated, regressed, and skipped epochs reject before admission. A loaded epoch of `2^63-1` is exhausted and rejects before persistence or admission. Scheduler and diagnostic admission must return exact `None`. Each receives a separate intent copy from the validated intent returned to the caller, so callback alias mutation cannot alter the caller's result. Callback invocation, exact-type validation, every result-field read, and service-owned copying are closed exception boundaries. Even an exact slots dataclass structurally corrupted after construction, such as by deleting a field, becomes sanitized `ControlRejected`; no raw validation or copy exception escapes. This applies to desired state, persisted intent, scheduler/lifecycle/diagnostic status, setup generation, resource authority, scheduler-online boolean, and scheduler/diagnostic admission results as applicable. Malformed values, malformed admission results, or upstream exceptions become `ControlRejected`. Sanitized failures retain neither an upstream exception cause/context nor its private payload. This makes durable persistence the handoff point rather than an adapter-owned signal.

Allowed control transitions are:

- `STOPPED -> RUNNING` by Run;
- `RUNNING -> PAUSED` by Pause;
- `PAUSED -> RUNNING` by Resume;
- `RUNNING|PAUSED -> STOPPED` by Stop.

Run and Resume require `SchedulerPort.is_online` to return an exact boolean. `False`, malformed truthy values, and exceptions reject without creating a queued intent. Pause and Stop remain durable desired-state controls and are handed off even when offline. Quarantine and unquarantine require an exact account reference and go through the same persisted intent plus scheduler admission boundary; they never launch work.

Setup is allowed only while stopped. Its resource set is an explicit closed `Resource` set. The default is the empty set, so Home Gold, Home Elixir, Home Dark Elixir, Builder Gold, and Builder Elixir are all off unless explicitly selected. A resource selection is configuration intent only: this module exposes no transaction or resource executor and grants no spending path.

Debug Start requires an already-running Team and an exact integer duration from two through five minutes. It persists a diagnostic intent and hands it only to `DiagnosticPort`; it does not call the scheduler, change control mode, start/resume lifecycle, authorize spending, or select an image region/delivery destination. Debug Status is read-only and Debug Stop cannot change the run state.

Status is constructed as a frozen `StatusView` from immutable service-owned copies made immediately after validating exact scheduler/lifecycle/resource snapshot types and before invoking another port. Desired epochs are bounded as above; connectivity and lifecycle activity are exact booleans; sanitized slot indices are `None` or exact integers in `0..1023`; queue depth is an exact integer in `0..1,000,000`; next-due time is `None` or a syntactically and calendrically valid UTC `YYYY-MM-DDTHH:MM:SS[.ffffff]Z` scalar; current account is `None` or a valid opaque reference; and resource authority is an exact `frozenset` of exact `Resource` members. Later mutation of a port-owned snapshot cannot change the validated output. Port exceptions fail closed without retaining or copying exception payloads into the view.

`StatusBlockedReason` is the complete privacy-safe blocker vocabulary: `OFFLINE`, `NO_ELIGIBLE_ACCOUNT`, `QUARANTINED`, `LIFECYCLE_BLOCKED`, and `CONFIGURATION_BLOCKED`. `StatusOutcome` is the complete last-outcome vocabulary: `IDLE`, `SUCCEEDED`, `FAILED`, `DEFERRED`, and `STOPPED`. The status ports and view use exact members of those enums or `None`; arbitrary strings and subclasses are rejected. The view has no field for account names, player tags, instance names, paths, credentials, PID/HWND values, traces, screenshots, pixels, raw exceptions, or private configuration.

Debug Status accepts only an exact `DiagnosticStatus`: `active` is an exact boolean and `remaining_seconds` is an exact integer in `0..300`. The service returns a new service-owned copy, so later mutation of the port-owned object cannot alter the validated result. Malformed diagnostic snapshots and diagnostic-port exceptions fail closed without retaining private exception payloads.

## Port ownership

- `AuthorizationPort` is the sole authorization decision.
- `DesiredStatePort` is the sole durable desired-state/command-intent writer.
- `SchedulerPort` is the sole admission and queue handoff/read model. It is a local `Protocol`; this module does not import or reproduce the parallel SCH1 scheduler contract.
- `LifecyclePort` is read-only here and exposes only a sanitized status snapshot. It is a local `Protocol`; no lifecycle implementation is imported.
- `SetupPort` owns future validated configuration staging/activation.
- `ResourceAuthorityPort` exposes only the current enabled set for redacted status.
- `DiagnosticPort` owns bounded diagnostics without scheduler or lifecycle authority.

There is intentionally no transaction, gameplay, process, input, transport, Discord, spending, frame, private-path, or executor port in this service. A future coordinator may implement the injected protocols only after its own authorization, admission, transaction, lifecycle, and resource gates are reviewed; adapters still receive only the application service.

## Local proof map

`tests/test_application_service.py` uses synthetic Team/account/operator references only and proves:

1. the adapter's supported public API contains only `submit`, the module keeps no live-service registry, missing/malformed private dispatch state fails closed, denied authorization cannot be bypassed through supported submission, and class-qualified dispatch ignores instance-shadowed service methods/helpers while rejecting fake/subclass services;
2. malformed exact-type references and every missing exact Actor/Command field fail as sanitized `ControlRejected` before authorization or persistence;
3. invalid state transitions and malformed desired-state snapshots fail before durable mutation;
4. offline or malformed scheduler-online results reject without queuing;
5. Run/Pause/Resume/Stop hand only a fully matched, snapshot-bound persisted intent with exactly the next loaded epoch to the scheduler port, reject stale/regressed/skipped epochs, fail closed at epoch exhaustion before persistence, require exact-`None` admission, and return a separate immutable value copy;
6. quarantine/unquarantine require an account and use the same validated durable admission handoff;
7. Setup defaults every resource authority off and validates its returned generation reference;
8. Status validates bounded scheduler/lifecycle/resource ingress and exposes only closed privacy-safe reason/outcome enums in its fixed typed view;
9. Debug is bounded, validates diagnostic ingress, requires an already-running Team, preserves run mode, and never reaches scheduler admission;
10. malformed port values, deleted fields across every exact dataclass port-result type, and upstream exceptions fail closed before scheduler/diagnostic forwarding; setup, resource-authority, online-boolean, and admission-result boundaries remain exact and sanitized; admission exceptions retain no cause/context; callback mutation cannot change snapshotted actor/command decisions or returned intents; irrelevant per-kind fields reject before callbacks; and post-validation mutation of port-owned status/debug snapshots cannot alter service output.
