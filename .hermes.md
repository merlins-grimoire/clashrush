# Clash Rush project law

## Authority (highest first)
1. Explicit current owner instruction/decision.
2. Current `clashrush-mvp` gate and its attached exact decision package.
3. [Current architecture index](docs/architecture/CURRENT.md).
4. Approved ADRs within their exact scopes.
5. Current code/tests for as-built behavior.
6. Reference/historical documents and skills.

A lower source cannot grant authority withheld by a higher source. Kanban owns task
status and owner gates; Git commit/tree owns revision identity; CURRENT.md owns the
architecture index. Historical reports/plans/reviews preserve evidence only. Main
code presence is not review, acceptance, runtime admission, or release.

## Donor-first
Before designing substantial behavior: trace pinned BasePilot, then pinned CoC_Bot,
then the relevant comparison donor; select the largest coherent compatible slice;
replace only incompatible boundaries; design locally only for real donor gaps.

## Revision and review
Every code-changing card uses an explicit isolated worktree/branch; no direct main
mutation. Every handoff records base commit/tree and result commit/tree (or exact
staged-tree identity for an owner-authorized no-commit handoff). Review applies only
to the exact reviewed tree. Production-code changes after PASS require focused
re-review. Commit presence never equals acceptance.

Contract → donor trace → behavioral REDs → complete implementation → focused tests
→ canonical tests when applicable → exact-tree handoff → one substantive review
→ at most one normal corrective pass. A second failure of the same seam means
REASSESS, not more micro-patching.

## Standing workflow and safety
Adopt [bounded offline autonomy and its owner stop conditions](docs/governance/development-workflow.md#1a--standing-offline-autonomy)
inside an explicitly adopted milestone only. Follow the linked detailed workflow;
no new milestone or live grant arises from standing law.

Fail closed on uncertainty. Exactly one host-wide game-input/lifecycle owner;
worktrees do not isolate the cursor. Native/gameplay input, capture, admission,
account switching, package install/update and external publication require exact
current authority. Offline readiness is not native/live acceptance. No unapproved
End/Surrender/restart fallback. Apply the canonical [currency policy](docs/product-policy/spending.md)
separately from action/executor/run authority.

Apply the canonical [privacy policy](docs/governance/development-workflow.md#3a--image-privacy-and-provider-policy)
and [future-live policy](docs/governance/development-workflow.md#4a--future-live-development).
The [live template](docs/governance/live-development-envelope-template.md) is inactive.

## Historical material and Ponytail
README, docs, research, old reports, skills and donor notes are not automatically
current architecture. Respect the status banners and CURRENT.md index. Do not
follow historical, superseded, proposed, rejected, parked or unresolved text as an
implementation instruction.

Ponytail Lite only, subordinate to the full contract. “Minimum” means the smallest
COMPLETE contract-preserving donor-backed solution, not the fewest lines/tests/files.

## Current status
Read [CURRENT.md](docs/architecture/CURRENT.md) for mutable gates and completed
scoped offline exceptions. Standing workflow cannot override a current hold.
